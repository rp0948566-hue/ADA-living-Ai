Jev: what it is, what it has, what is missing

Jev is a voice-first assistant that controls a whole computer. This page is meant to be handed to another AI: the pipeline, the parts that already work, the parts that do not, and a spec for the next feature (a "voice remote" like the Instagram video you sent).

1. What Jev is

Jev started as a Mac app (Swift overlay plus a Python brain, jev.py) where you hold a hotkey, say what you need, and an AI does it on your computer. This project is the Linux port, renamed Jev, running on GNOME Wayland. The Mac code path is untouched. On Linux, jev.py swaps in linux/jev_linux.py and stand-ins for every Mac-only piece.

It runs on an API model you choose (currently Gemini gemini-2.5-flash through its OpenAI-style endpoint). There is no local model any more. Safe mode is off (full access), sudo for package tools is on, and there is a hard gate that still blocks the dangerous commands.

2. Pipeline: from your voice to an action

  B --> C["host.py: GTK3 + WebKit box (ui/ui.html), shows words, Allow cards, answers"]
  C --> D["worker.py starts jev.py (the brain) and reads its output lines"]
  D --> E{"Simple command?
(open app, play song, own shortcut)"}
  E -- yes --> F["Runs instantly, no AI call"]
  E -- no --> G["run_local: system prompt + your memory + one bash tool, sent to the API model"]
  G --> H["Model answers or asks for a tool call"]
  H --> I["Gate: hard safety check on every command (deletes, sends, purchases ask first)"]
  I --> J["Tools: hands.py (AT-SPI + uinput keys/clicks), wm.py (windows), shot.py (screen + OCR), browser.py (Playwright browser), calendar, sysmon, bin/ shims"]
  J --> G
  F --> K["Result line to the box"]
  H -- final answer --> K
  K --> L["voice.py / say: Piper neural voice reads it aloud; ui shows it"]

      5. The new feature: Voice Remote

      Goal: speak, and Jev drives whatever app is in front of you, with no AI call for simple commands, so it feels instant like the video. Anything that is not a known command still goes to the AI as today.

      How you will interact with it

      Idle

      Wake word or hotkey turns it on. A small pill at the dock shows the state: listening, typing, thinking.

      Command

      You say a short phrase. If it matches the command list, Jev does it in about a second. No AI call, no quota used.

      Dictation

      Say "type". Everything you say after goes, cleaned up, into the focused text field. Say "send it" to press Enter, or "stop typing" to leave.

      Ask the AI

      Anything else, like "check the reviews of this laptop", goes to the brain as now, with the pill showing "thinking".

      Command set for version 1

      You sayJev doesBuilt from
      "type" / "stop typing"Dictation mode on or off, text typed into the focused fieldlisten.py + hands.py type
      "send it"Presses Enter in the focused apphands.py press enter
      "scroll down / up", "page down"Scrolls the focused windowhands.py scroll
      "go to Wikipedia", "go to Slack"Opens a site in the browser or switches to the appbrowser.py open, wm.py
      "personal life", "legal affairs"Jumps to that heading on the pageNew: find heading text via AT-SPI or browser, then scroll to it
      "switch to Codex", "next window"Brings that window forwardwm.py (limited on Wayland)
      "stop", "cancel"Stops speech and any running taskAlready exists (Esc / stop)

      What gets added

      • New module linux/voicecmd.py between listen.py and the brain. It holds a small grammar, matches each finished utterance to a command and calls hands.py, browser.py or wm.py. No match: pass the text to jev.py unchanged.
      • Mode state in host.py: idle, command, dictation, thinking. It drives the dock pill and the sound cues.
      • Faster end-of-speech for commands: short utterances close after about 0.5 s of quiet, long dictation keeps the 0.8 s used now.
      • Settings switch "Voice Remote" and a list of the user's own phrases, stored with the other settings in ~/.config/jev/settings.json.

      Safety

      Typing and Enter reach any focused app, so a wrong transcription can send a wrong message. Rules: "send it" works only right after dictation or when a text field has focus; destructive phrases never match the fast path and always go through the gate; the pill is always visible while Jev listens.

      Build order

      1. Grammar and matcher in voicecmd.py with unit tests (pure Python, no hardware).
      2. "type", "send it", "scroll" through hands.py; test in a text editor, then a browser.
      3. "go to" for sites and apps; heading jump.
      4. Dock pill and mode state; settings switch.
      5. Live test on the real mic, in a quiet and a noisy room.

      Risks

      • GNOME Wayland blocks reading and moving other windows. Typing through uinput works, but "switch to window" may stay limited. Untested here.
      • Whisper small on CPU adds about a second per utterance. A smaller model for commands only would cut that.
      • The Gemini free tier allows 5 requests a minute and 20 a day per model, so the fast command path matters more than the AI path.
